# Contributing

Contributions should keep the prototype's research boundary clear. Start by reading [README](README.md), [Technical note](TECHNICAL-NOTE.md), and [Future study](docs/future-study.md).

Run `make verify` before proposing a change. Include tests when behavior changes, and explain any change to a historical result, generated evidence, or public claim.

Do not add credentials, personal data, customer material, raw provider diagnostic records, or private project notes. Do not revise the v1 archive or preserved scientific engine files as ordinary maintenance. A new empirical study needs a new protocol and should not rewrite the completed archive.

Keep claims source-bound. A local pass shows only what the relevant check reports. It does not establish a fresh model result, external validity, independent review, or a release.
